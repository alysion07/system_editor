
## 기술 명세서: NodeInspector 개선 및 입력 파일 생성

문서 버전: 1.1
작성일: 2025년 9월 3일
프로젝트 목표: NodeInspector의 기능을 고도화하여, GUI를 통해 완전한 시뮬레이션 입력 파일(SMART.i, copain.i 형식)을 생성합니다.

1. 개요

1.1. 목표 (Goal)

본 프로젝트는 사용자가 그래픽 인터페이스(GUI) 환경에서 각 컴포넌트의 속성을 직관적으로 편집하고, 그 결과를 바탕으로 시뮬레이터가 즉시 실행할 수 있는 완전한 형태의 텍스트 기반 입력 파일을 생성하는 것을 목표로 합니다.

1.2. 범위 (Scope)

* UI/UX 개선: NodeInspector가 조건부 필드, 동적 테이블 등 복잡한 데이터 구조를 사용자 친화적으로 렌더링하도록 개선합니다.
* 아키텍처 표준화: 모든 컴포넌트 정의 파일의 데이터 구조를 일관된 스키마(tabs/cards/fields)로 통일합니다.
* 파일 생성 자동화: UI에서 입력된 데이터를 바탕으로, 지정된 포맷의 전체 텍스트 파일을 생성하는 로직을 구현합니다.
* 정확성 검증: 생성된 파일이 참조 파일(SMART.i, copain.i)과 일치하는지 확인하여 신뢰성을 확보합니다.

2. 요구사항 분석 및 발견

2.1. 분석 과정

1. 매뉴얼 분석: public/ref/parts_of_input_manual 디렉토리에서 PDF 형식의 입력 명세서를 발견했습니다. SNGLVOL.pdf를 분석하여 "카드(Card)"와 "워드(Word)" 기반의 복잡한 입력 형식을 확인했습니다.
2. 기존 코드 분석: src/components/node-editor/components/ 내의 PIPE.js, SNGLVOL.js 등 기존 컴포넌트 정의를 분석했습니다. 이를 통해 tabs/cards/fields 계층 구조와 유효성 검사(validators), 포맷팅(formatters) 로직이 결합된 아키텍처 패턴을 발견했습니다.
3. 최종 출력물 분석: public/resource/copain.i 파일을 분석하여, 최종 결과물은 전역 설정, 여러 컴포넌트 데이터가 포함된 완전한 구조여야 하며, 반복 데이터를 압축(값 반복횟수)하여 표현해야 함을 확인했습니다.

2.2. 핵심 요구사항

* 지능형 UI: NodeInspector는 다음 기능을 필수로 지원해야 합니다.
    * 조건부 렌더링: 특정 값에 따라 UI 요소가 동적으로 표시/숨김 처리되어야 합니다.
    * 동적 테이블: 입력 값에 따라 테이블 행의 수가 자동으로 변경되어야 합니다.
    * 특수 컨트롤: 플래그 조합, 메시 시각화 등 복잡한 데이터를 위한 전용 UI가 필요합니다.
* 스키마 기반 아키텍처: UI와 로직은 컴포넌트별 JS 객체(스키마)에 의해 제어되어야 합니다.
* 완전한 파일 생성: 생성 파일은 시뮬레이터가 즉시 실행 가능하도록 모든 구조(헤더, 전역 설정, 데이터)를 포함해야 합니다.

3. 최종 설계 및 구현 계획

기존 아키텍처를 존중하고 확장하는 방향으로 다음의 3단계 계획을 수립했습니다.

3단계: 파일 생성 및 검증 (상세)

* 목표: copain.i와 같이 즉시 실행 가능한 완전한 구조의 입력 파일을 생성합니다.
* `smartFileGenerator.js` 로직 강화:
    1. 전체 파일 구조 생성: 생성기는 먼저 파일 헤더와 전역 제어 카드(100번대 카드 등)를 출력합니다.
    2. 컴포넌트 데이터 포맷팅: 노드 에디터의 모든 컴포넌트를 순회하며, 각 컴포넌트 정의 파일 내의 formatters를 호출하여 해당 컴포넌트의 데이터 카드 문자열을 생성합니다.
    3. 압축 포맷 적용: formatters 내에서, 테이블 데이터의 값들이 모두 동일한 경우 값 반복횟수 형태로 압축하여 출력하는 로직을 구현합니다.
    4. 최종 조립: 생성된 모든 문자열 조각들을 copain.i와 동일한 순서로 조립하여 최종 파일을 완성합니다.
* 검증: copain.i와 SMART.i를 "정답"으로 삼아, UI에서 동일한 시나리오를 구성하고 생성된 파일과 비교하여 정확성을 검증합니다.

1단계: 컴포넌트 정의 표준화 (Refactoring)

* 목표: 모든 컴포넌트 정의 파일이 일관된 tabs/cards/fields 구조를 갖도록 리팩토링합니다.
* 주요 작업: SNGLVOL.js를 PDF 매뉴얼의 모든 요구사항을 반영하여 가장 상세한 표준 모델로 업데이트합니다. 이후 다른 컴포넌트들도 이 구조에 맞게 수정합니다.

2단계: NodeInspector 기능 강화

* 목표: 표준화된 스키마를 해석하여 지능형 UI를 동적으로 생성하도록 NodeInspector를 개선합니다.
* 주요 작업: 동적 테이블 행 생성, 커스텀 컨트롤 렌더링, 강화된 유효성 검사 엔진을 구현합니다.
